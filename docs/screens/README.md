# Скриншоты Ymuse (живые данные Яндекс Музыки)

Сняты с реально запущенного `Ymuse.exe` (Release, WebView2) через DevTools-протокол
WebView2: без заранее подготовленных данных, без аккаунта.
Запуск для съёмки: `YMUSE_CDP_PORT=9333 Ymuse.exe` (хук только для диагностики,
в обычной работе не используется) + `Page.captureScreenshot`.

Экраны 03–07 открыты в гостевом режиме: каталог станций, настройки потока и поиск
Яндекс отдаёт без токена, а личные плейлисты и очередь персональных станций — только
аккаунту. Приложение говорит об этом прямо, а не показывает пустоту.

## Что нашла и исправила визуальная проверка

1. **Не работала навигация в сайдбаре** — у кнопок был `data-nav`, но не было `data-act`, поэтому делегированный обработчик их игнорировал.
2. **Каталог станций, настройки и поиск были заперты за входом**, хотя API отдаёт их анонимно → добавлен гостевой режим с честными объяснениями.
3. **Панель настроек обрезала текст страницы** → при открытом drawer контенту добавляется отступ справа.
4. **Повторяющийся текст** в уведомлении о необходимости входа → одна причина, с пунктуацией.
5. **Пустые заголовки «Настроение»/«Занятие»** на экране входа и лишняя линия внизу сайдбара → скрываются.
6. **`favicon.ico` 404** в консоли WebView2 → data-иконка, консоль чистая.
7. **Серая заглушка вместо обложки станции** → используется `icon.imageUrl` из API.
8. **Карточка входа обрезалась снизу** на экране кода: приложение всегда резервировало 84 px под плеер, даже когда он скрыт → раскладка переведена на flex, и карточка целиком видна.
9. «Пустые» обложки в поиске оказались артефактом слишком раннего кадра — снимок теперь ждёт загрузки картинок (400×400, загружены).

Проверено на снимках: ни одной пустой панели, обрезанного текста или ошибки в
консоли (`errors: none`); каждая строка списков — реальные данные API.
