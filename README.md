# Ymuse — лёгкий клиент Яндекс Музыки

Нативное приложение для Windows: тонкая оболочка WPF + WebView2 (уже установлен в Windows)
и интерфейс на чистом HTML/CSS/JS — без Electron, фреймворков и сборки фронтенда.

Память: десятки мегабайт вместо сотен у Electron-клиентов; сам `Ymuse.exe` — около 150 КБ
плюс общий WebView2 Runtime, который уже есть в системе.

## Что умеет

- **Плейлисты** — список своих плейлистов, треки, «Слушать».
- **Поиск** — треки, альбомы, плейлисты.
- **Поток (радио)** — станции по настроению, занятию, жанрам, эпохам и подборкам.
- **Настройки потока** — для каждой станции: характер (`moodEnergy`), разнообразие (`diversity`),
  язык (`language`), применяются через `POST /rotor/station/{id}/settings2`.
- **Плеер** — очередь, автопродление волны, переключение, прогресс, громкость,
  фидбек в ротор (начало трека / дослушан / скип), чтобы волна подстраивалась.
- **Гостевой режим** — без входа доступны каталог станций, их настройки и поиск;
  прослушивание и личные плейлисты требуют аккаунта, и приложение говорит об этом прямо.
- Вход через Яндекс: код устройства (device flow) или готовый OAuth-токен.

Скриншоты работающего приложения и разбор найденных при проверке дефектов —
в [`docs/screens/`](docs/screens/README.md).

## Запуск

```bash
dotnet run --project src/Ymuse
```

Или соберите и запустите готовый exe:

```bash
dotnet build src/Ymuse -c Release
src\Ymuse\bin\Release\net9.0-windows\win-x64\Ymuse.exe
```

Сборка self-contained: .NET 9 Desktop Runtime внутрь уже включён, на машине
пользователя ставить его не нужно — достаточно распаковать папку и запустить `Ymuse.exe`.
Единственное внешнее требование — Edge WebView2 Runtime (в Windows 10/11 он обычно уже установлен).
Для сборки из исходников нужен .NET 9 SDK.

## Вход

1. **«Войти через Яндекс»** — открывается окно с настоящей страницей Яндекс ID.
   После входа Яндекс редиректит с токеном, приложение перехватывает его и сразу
   закрывает окно. Пароль вводится только на сайте Яндекса.
2. Либо «Войти по коду»: откройте `https://ya.ru/device` и введите показанный код
   (удобно, если вход нужен на другом устройстве).
3. Либо вставьте готовый OAuth-токен.

Токен хранится только локально: `%APPDATA%\Ymuse\settings.json`.
Без входа доступны каталог станций, их настройки и поиск — гостевой режим.

## Автообновление (тихое, без настройки)

Канал определяется автоматически:

1. `YMUSE_UPDATE_URL` или `settings.updateUrl` — если заданы, это JSON-манифест;
2. `channel.json` рядом с `Ymuse.exe`: `{"manifest": "https://..."}` или
   `{"repository": "https://github.com/o/r"}` — канал едет вместе со сборкой, настраивать ничего не нужно;
3. git-remote проекта: `.git/config` рядом с приложением до 6 уровней вверх (включая
   worktree/submodule через `.git`-файл), `RepositoryUrl` в сборке или `GITHUB_REPOSITORY`;
   версия и ассет берутся из GitHub Releases API — `/releases/latest`, затем `/releases`;
4. если канала нет — проверка молча пропускается.

Ассет выбирается под сборку, а не первый попавшийся: zip для Windows x64
(`x64`/`x86_64`/`amd64`/`win64`, msvc предпочтительнее), arm/aarch64/i686 и
установщики отбрасываются. Нет подходящего ассета — тишина, без ошибок в UI.

Проверка идёт при старте и раз в 6 часов; скачивание — в staging, SHA-256 сверяется
с `digest` из GitHub API (или `sha256` из манифеста), при несовпадении файл и staging
удаляются. Новая версия применяется отдельным процессом **только после штатного выхода**:
воспроизведение не прерывается, настройки и токен в `%APPDATA%` не затрагиваются.
Диагностика без диалогов: `%APPDATA%\Ymuse\update.log`.

Канал этого проекта — **https://github.com/Roqov/ymuse**: приложение находит его само
по `git remote` рабочей копии, по `RepositoryUrl` в сборке (зашит в `Ymuse.csproj`)
или по `channel.json` рядом с exe — поэтому и распакованная из релиза папка видит канал.
Проверено на настоящем релизе `v0.2.3`: скачивание, SHA-256 из `digest`, применение
после выхода и перезапуск на новой версии — а также на чистой распаковке zip вне
репозитория и без установленного .NET 9: запуск, канал `github:Roqov/ymuse`
и «обновление не требуется» без загрузки.

Выпуск новой версии:

```bash
# 1) поднять версию в src/Ymuse/Ymuse.csproj (<Version>0.2.3</Version>)
dotnet publish src/Ymuse/Ymuse.csproj -c Release
# 2) упаковать содержимое src/Ymuse/bin/Release/net9.0-windows/win-x64/publish в zip
#    RuntimeIdentifier=win-x64 и SelfContained=true уже заданы в csproj, поэтому
#    в папке лежат hostfxr.dll, coreclr.dll и WPF — .NET на машине не нужен;
#    профиль Ymuse.exe.WebView2 и *.pdb в zip не включать
# 3) создать релиз с тегом v0.2.3 и приложить zip
```

Имя ассета должно содержать `win-x64` (`ymuse-0.2.3-win-x64.zip`) — по нему выбирается
сборка под платформу. GitHub сам считает `digest`, отдельная контрольная сумма не нужна.

Либо задайте `updateUrl`/`YMUSE_UPDATE_URL` с манифестом:

```json
{ "version": "0.3.0", "url": "https://host/ymuse-0.3.0.zip", "sha256": "<hex>" }
```

В zip кладётся содержимое папки публикации (`Ymuse.exe`, `Ymuse.dll`, `wwwroot`, WebView2-dll,
рантайм .NET 9 и WPF) — распакованная копия запускается на чистой Windows без установки .NET.
Статус виден внизу сайдбара: версия, канал и, если сборка уже скачана, — «обн. 0.3.0 при выходе».

Приложение не отправляет данные никуда, кроме `api.music.yandex.net` и `oauth.yandex.ru`.
Полное качество и полные треки доступны при активной подписке Плюс; без неё сервер отдаёт
только 30-секундные превью.

## Структура

```
src/Ymuse/
  MainWindow.xaml(.cs)   окно + мост JS ↔ C#
  LoginWindow.xaml(.cs)  вход через окно Яндекса, перехват токена
  Bridge/Rpc.cs          методы, вызываемые из интерфейса
  Api/YandexClient.cs    работа с API, OAuth (device flow и токен)
  Api/Models.cs, J.cs    модели и разбор JSON
  Core/SettingsStore.cs  хранение токена и настроек
  Core/UpdateService.cs  тихое автообновление
  wwwroot/               интерфейс: index.html, styles.css, app.js
```

## API

Используется неофициальный API Яндекс Музыки (`https://api.music.yandex.net`):
`/search`, `/users/{uid}/playlists/*`, `/albums/{id}/with-tracks`,
`/rotor/stations/list`, `/rotor/station/{id}/{tracks,info,settings2,feedback}`,
`/tracks/{id}/download-info` + `/get-mp3/<sign>/...`.
